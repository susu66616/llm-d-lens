打开 **Model Catalog（模型目录）**选择模型。搜索与分类筛选共同生效，不区分大小写，
每个搜索词都必须匹配模型元数据。**Clear filters** 同时清空两种筛选。

## 一条流程，两种决策方式

| 模式 | 决策规则 |
| --- | --- |
| **Manual** | 自动组合适用且已支持的优化，优先源码验证后的覆盖范围；无偏好时以较少资源打破平局，不调用 LLM。 |
| **Agentic** | 根据目标、负载和可用证据比较经过校验的候选；显式选择的 AI 提供方可以提出候选并排序，回退情况会明确标注。 |

两者共用 **Target（目标）→ Deployment plan（部署方案）→ Deploy and observe（部署与观察）**。
API 模式名仍为 `manual` 和 `agentic`。
已有部署、兼容 API 和历史计划不会被删除。

“启用更多机制”不代表占满资源或性能最好。缺少前提证据保持 **unknown（未知）**；
缺少组合适配器标为 **unsupported（未支持）**，不称为已证明互斥。当前适配器没有覆盖任意 Guide 组合。

## 选择目标

1. 选择模型后，先选择醒目的 **Manual** 或 **Agentic** 卡片。
2. 查看简洁的环境卡：有就绪集群时自动预选，部署名称自动生成。
   **Change setup**将集群、名称和模型缓存控件集中在弹窗内。
   没有集群时可选择真实环境，或点击 **Try Intel XPU mock**。
3. Manual 在当前页展示兼容默认方案；Agentic 在同一页提供 Balanced、
   Low latency、High throughput 目标。点击 **Build Manual plan** 或
   **Build Agentic plan**直接进入生成的方案，无需填写数值参数。
   **1–3 Walkthrough**通过遮罩逐步引导这些控件。

模型文件缺失时使用 **Prepare model cache**。
参阅[模型缓存](/user-guide/model-cache)和[存储](/user-guide/storage)。

### 无硬件体验

**Try Intel XPU mock**预置 Qwen3-0.6B、两个模拟节点、四张 Intel Arc Pro B60
（每张 24 GiB）和就绪的模拟缓存。镜像与设备资源名称来自已注册硬件 profile，
不会创建集群或缓存记录。Manual 直接生成示例方案；Agentic 只需选择一个目标，
使用明确标注的演示规则。两种模式都不调用 AI 提供方、不预测性能。

按 **Serving flow → expand a group → configure a setting → Review & simulate** 体验：点击阶段查看优化，切换前缀缓存
或分块预填充，修改副本数、TP 和引擎限制，查看或下载同步变化的模型服务器 YAML 片段。
此 Mock 覆盖三个引擎设置，不代表所有 Guide 或完整 llm-d 部署包。
审阅窗口集中展示 YAML、检查结果及折叠的 **Mock scenario** 选择器，
点击 **Confirm simulation**开始模拟。请求关系图复用真实规划器的逻辑视图，不表示已验证的 Mock 路由安装。
**Insufficient capacity**会阻止模拟部署；**Restore mock capacity**恢复就绪场景。
确认后展示三个本地模拟启动状态，不发送部署 API 请求。
**Use a real cluster**退出预览；**1–3 Walkthrough**提供分步遮罩。

初始上下文长度使用模型卡片的准确 `contextLength`，仅缺失时使用 `4096`。
支持范围为 `256` 到 `1048576`，不会静默缩短。运行镜像来自目标硬件 profile。
副本数、TP 和运行参数在生成后编辑，不再作为初始部署输入。

## 填写需求

点击 **Build Manual plan** 或 **Build Agentic plan**，无需选择 Guide。
默认折叠的可选分组记录请求长度、并发或 QPS、延迟目标和
加速器使用上限，全部默认未指定。模型上下文不代表真实请求长度，平均输入与 P95 独立。
后端自动发现硬件并选择运行参数。

Manual 无需负载问卷，也不调用 LLM。Agentic 优先显示目标选项；
展开 **Describe a goal（描述目标）**并显式选择 AI 提供方后可填写自然语言目标，已有目标会保持该区域展开。
仅提取明确表达的定性负载特征，显示提取结果，且结构化值优先于 AI 推断。
数值限制不会自动推测。未选择 AI 时使用结构化输入和规则推荐。
未知或预期较低的复用率不会阻止技术兼容的优化组合。
默认取舍为 **Balanced（均衡）**，不是吞吐优先。历史输入保持原样。
Agentic 默认保留三个推荐，规划截止时间为 60 分钟，不自动执行实测。

后端强制执行加速器上限和必须 / 禁止的机制。实际空闲资源始终优先。
必须启用的机制缺少技术支持、要求的组合不兼容或资源不足时会明确失败。
配置能放进显存不代表已经满足延迟目标。

Manual 保留不同已支持能力族用于源码检查。两种模式都独立组合前缀亲和路由、CPU KV 缓存
和聚合或 P/D 服务；精确路由、独立分层缓存仍是受支持的实现。
这些是规划候选，不代表选中源码版本已经支持组合。CPU 缓存每个服务副本最多 8 GiB，
所有副本合计不超过已发现空闲主机内存的 25%，包含 P/D 两类角色；内存未知时不自动授权卸载。
源码渲染器检查连接器、相同运行镜像、固定版本和放置条件后，才将计划缓存标为启用。
存在模型 / 显存容量估算时，序列数也受其约束。

先最大化兼容能力覆盖，再按已知目标缺口和偏好打破平局：吞吐优先 P/D，其次前缀路由；低延迟优先前缀路由；
成本优先较少加速器；可靠性优先多个服务副本。仍然相同时选择较少加速器。
无偏好时也用较少资源打破覆盖相同的平局。选择说明公开这一规则，
不代表实测吞吐或延迟结论。不支持的组合不会被悄悄叠加。

按负载规划目前使用 AIC 原生推荐，只接受并发数或请求率之一。
找不到兼容的负载预测时会报错，不会静默改成无负载约束的估算。

## 审阅与编辑

- 单一标题显示 **Manual plan** 或 **Agentic plan**、模型和集群。
  **Change setup**返回环境和部署名称设置。横向摘要集中显示拓扑、资源、优化数量和校验状态。
- **Serving flow（服务流程）**使用横向 Request → Endpoint selection → Prefill → Decode → Response 主路径。
  聚合服务把两个计算阶段放入同一个 Model server 边界，P/D 使用独立边界。
  缓存索引、KV 缓存、计算配置和服务管理连接到实际作用的阶段。
  这些是逻辑处理与配置关系，不是实时流量或实测放置。

  所有功能组默认可见，显示已配置数量与摘要。点击分组，在图中展开内部优化，包括关闭与不可用项；
  每组每页最多四项，展开另一组时收起前一组。点击优化项，直接打开其源码、路由或运行参数配置抽屉。
  展开组内的 **Stage parameters** 可打开副本数等更完整的阶段参数（仅限源码声明的可配置内容）。受支持的开关和详细编辑器沿用现有兼容性检查，不可用项保留只读原因说明。
  不再设置独立 Stage configuration 表格或全局 All settings 可见性开关。
  编辑后先应用并检查资源，再审阅部署；关闭抽屉会保留待应用修改，如需放弃请明确丢弃。
  窄屏可横向滚动图形，可选的 **3D technical view（3D 技术视图）**保留基础设施拓扑。

  当前方案不符合目标时，使用 **Refine with Agentic**，选择目标，也可调整已有的负载与限制。
  同一模型、集群和运行参数会带入独立的新建议；精确的源码编辑仍保存在原方案中。
  **Return to previous plan**恢复已保存的方案，不会重新生成。请先应用或丢弃待处理修改。
  新建议仍需资源检查和明确部署确认，不代表性能实测结果。返回历史仅在当前设置页打开期间保留。
  Mock 仅支持目标选择，使用模拟规则。 Prefix caching 和 Chunked prefill 提供 **Enabled / Disabled** 配置及参数预览；点击 **Apply changes** 才更新 Mock 方案与 YAML，**Cancel** 放弃本次编辑。未支持的 Mock 设置保留不可用原因。
- **Technical details: source Guides and all parameters（技术详情：源码指南与全部参数）**
  收纳固定版本的完整指南索引，包括不支持项及原因。已选指南保留兼容性选项和变量。
  前缀亲和路由与精确索引仍是独立优化点。
- 点击优化项从图中打开源码、路由或运行参数抽屉；可选的 3D 视图保留侧栏。技术详情提供
  **All deployment parameters（全部部署参数）**及 **Final YAML（最终 YAML）**。
  切换优化会保留不相关的最终编辑；冲突时阻止应用，不会静默丢弃。
  请撤销冲突，或明确丢弃最终参数编辑。旧快照缺少编辑基线时，基础配置变化需要明确处理。
  原生 CPU 缓存禁用后保留容量，供再次启用。没有新增独立部署通道。
- **Apply changes and check resources（应用修改并检查资源）**保存并校验新快照。
  未应用编辑会阻止部署，自动推荐保留用户明确选择。Manual 尽量覆盖兼容优化，但仍检查
  外部前置条件、未确定选项及资源上限。Agentic 使用同一编辑器；
  两种模式都考虑负载预设之外的兼容源码优化。

源码加载失败时展示真实原因并可重试。旧运行可通过
**Load Guides and build source configuration（加载指南并构建源码配置）**升级，不局限于原预览。
源码版本变化时，必须明确采用新版本后再应用编辑。**Workload and limits（负载与限制）**
仍可重建需求而不修改运行中部署。折叠的 **More planning tools / optional（更多规划工具，可选）**保留 Agentic 的
**Alternatives（候选方案）**和 **Benchmark tests（基准测试）**。候选方案比较已审阅源码配置，
不会宣称未测量的性能。

## 生成、检查与部署

1. 两种模式都自动生成并检查 YAML。Manual 补齐源码已声明的运行参数，
   按渲染后真正启用的能力覆盖选择，而非第一个通过的 Guide。
   全部失败时保留推荐并阻止部署，解决问题后使用 **Retry checks（重试检查）**。
   用户显式选择的候选不会被悄悄替换。
2. 审阅警告、依赖和待检查项。渲染不会安装资源；集群准入、运行就绪和负载性能仍待验证。
3. 选择已审阅的模型 **Inference Service（推理服务）**，不要选择 EPP 或指标服务。
   **Review & deploy**集中打开 YAML 和检查结果，**Ready for your confirmation（等待确认）**
   给出结论。点击 **Confirm deployment**确认当前准确配置的校验和与所选端点。
   配置快照变化后必须重新审阅。
   审批会刷新容量，并通过共享部署生命周期提交已审阅清单。
4. **Deployment execution（部署执行）**显示实际组件状态和日志入口。
   只有执行成功且所有组件报告就绪时，摘要才显示 **Deployment ready（部署就绪）**。
   **Open deployment（打开部署）**进入筛选后的部署列表，查看端点、监控和评测；
   就绪不代表负载性能已经验证。参阅[管理部署](/user-guide/deployments)。

命名空间绑定、已注册存储挂载等部署时适配仍遵循现有 Deploy 契约。
规划检查通过不保证集群准入或启动成功。

## 证据与受控实测

界面区分**推荐方案**、**性能预测**、已测候选，以及**指定负载和预算内已验证的最佳候选**。
仅出现在实测排名中不代表该方案是第一名，任何结果都不宣称全局最优。

每次生成或重新计算推荐时，Lens 都会先按所选模型查询已发布的公开 SQL 实验，
再进行 AIC 规划。配置外部 AI 提供方时，适用的公共实测证据在候选生成和排序中优先于
AIC 估算；公共证据缺失或不适用时，AIC 作为补充。实时资源硬约束和明确的操作偏好仍然有效，
不同硬件、负载、运行时版本、拓扑或指标统计口径的结果不能直接互换。

公共检索还会按目标集群实时探测的加速卡型号过滤，而不是按集群名称判断。
厂商修饰及分隔符差异可以匹配，但显存大小和 PCIe/SXM 型号仍严格区分。
未知或混合硬件会明确提示；没有匹配结果时不会回退到其他硬件家族。

公开基准记录的运行时后端缺失、为空或为 `unknown` 时，检索和规划上下文默认按 `vllm` 处理。
明确标注的其他后端保持原值，不匹配 vLLM 计划。该资料库默认规则不会推断运行时版本，
也不会改写原始证据。

在 **Planning evidence（规划证据）** 中查看 **Public SQL measured observations**，
可检查检索状态、原始数值与单位、来源路径、版本和校验和。无匹配、查询失败或缺少已认证的全局
`benchmark-rag:query:read` 权限时，页面会明确提示，并继续使用原有证据规划。
包含公共 RAG 观测数据的计划仍要求相同的读取权限。
没有外部 AI 时，检索结果仅作为上下文保留，不会自动转换为确定性性能预测，也不会改写显示的 SLO 判断。

内部 SQL 实验单独列出。Agentic 规划使用 SQL 证据，
不要求安装文档搜索服务或独立搜索页。

通过 **Benchmark tests（基准测试）**准备允许测试的 Agentic 计划。
实测仍需单独确认，并明确固定负载、候选、资源 / 时间 /
运行次数预算及重复次数。实测复用现有受限的 Deploy/Evaluate 执行器，清理自身创建的部署，
不会自动修改已有部署。中断的实测保留记录，供显式清理。
源码测试需要先 **Check all source candidates（检查全部源码候选）**，
并为每个已选候选明确选择审阅过的推理 Service。缓存变体在指南编辑器中配置并渲染；
测试不会替换为未经审阅的提供方模板，也不会悄悄添加 native 缓存变体。
选择实测优胜方案会恢复其已审阅源码配置。

新流程的运行与修订会随规划快照持久化。刷新可恢复已保存的计划；集群会话过期时，
必须先恢复有效会话再继续操作。修改需求会生成另一个计划。

当前目录不能证明全部优化及任意组合均可部署。可用性来自所选源码版本与组合适配器；
未支持、外部操作及未适配项保留限制说明，不会消失。缺少源码证据不视为已验证。
直接调用 vLLM 的开关补齐可使用强制运行时能力检查，
但不伪称支持已经验证；缺少适配器的能力不会启用。最终部署仍需真实集群与负载实测验收。
