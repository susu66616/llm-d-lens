## 配置和审阅 Manual 或 Agentic 方案

先在两张醒目的卡片中选择 **Manual** 或 **Agentic**，再查看简洁的环境卡。
存在就绪集群时会预选，部署名称自动生成，模型缓存自动检查。
**Change setup**集中打开集群、名称与模型缓存控件；模型缓存未就绪时仍需准备模型文件。
两种模式都不要求先填写硬件规格或选择 Guide。

**Build Manual plan**组合适用、已支持且兼容的优化并进入配置审阅。
Agentic 在同一入口页提供 Balanced、Low latency、High throughput，
点击 **Build Agentic plan**直接进入生成的方案，没有额外问卷页。保留 Balanced 即可不填参数继续；恢复已有方案时保留其他已支持目标。
**Describe a goal（描述目标）**允许在明确选择 AI 提供方后填写自然语言需求；
否则 Agentic 使用规则推荐，界面会标明当前路径。两者都不代表已经获得实测最优解。

资源限制、负载、请求长度和延迟目标默认收起且可选。留空保持未指定，
重新编辑时已保存的约束会展开显示。**1–3 Walkthrough**逐步突出模式、设置和继续按钮。
方案中的 **Walkthrough**依次突出方案摘要、服务流程和统一审阅入口。
引导本身不生成、不修改、不批准方案；Skip 或 Escape 退出，高亮的真实控件仍可操作。

方案标题突出 **Manual plan** 或 **Agentic plan**，同时显示模型和集群。
**Change setup**返回设置，后端已有方案仍按原模式与目标保存。
**Serving flow（服务流程）**使用横向 Request → Endpoint selection → Prefill → Decode → Response 主路径。
聚合服务把两个计算阶段放入同一个 Model server 边界，P/D 使用独立边界。
缓存索引、KV 缓存、计算配置和服务管理连接到实际作用的阶段。
这些是逻辑处理与配置关系，不是实时流量或实测放置。

所有功能组默认可见，显示已配置数量与摘要。点击分组，在图中展开内部优化，包括关闭与不可用项；
每组每页最多四项，展开另一组时收起前一组。点击优化项，直接打开其源码、路由或运行参数配置抽屉。
展开组内的 **Stage parameters** 可打开副本数等更完整的阶段参数（仅限源码声明的可配置内容）。受支持的开关和详细编辑器沿用现有兼容性检查，不可用项保留只读原因说明。
不再设置独立 Stage configuration 表格或全局 All settings 可见性开关。
编辑后先应用并检查资源，再审阅部署；关闭抽屉会保留待应用修改，如需放弃请明确丢弃。
窄屏可横向滚动图形，可选的 **3D technical view（3D 技术视图）**保留基础设施拓扑。

当前方案不符合目标时，使用 **Refine with Agentic**，选择目标，也可调整已有的负载与限制。
同一模型、集群和运行参数会带入独立的新建议；精确的源码编辑仍保存在原方案中。
**Return to previous plan**恢复已保存的方案，不会重新生成。请先应用或丢弃待处理修改。
新建议仍需资源检查和明确部署确认，不代表性能实测结果。返回历史仅在当前设置页打开期间保留。
Mock 仅支持目标选择，使用模拟规则。 Prefix caching 和 Chunked prefill 提供 **Enabled / Disabled** 配置及参数预览；点击 **Apply changes** 才更新 Mock 方案与 YAML，**Cancel** 放弃本次编辑。未支持的 Mock 设置保留不可用原因。

**Technical details: source Guides and all parameters（技术详情：源码指南与全部参数）**
收纳集群固定 llm-d 版本的完整指南索引。
不可用、外部操作和未适配指南仍显示原因；列在索引中不代表指南或任意组合可以部署。
已选指南继续展示兼容性选项与源码变量。流程图包含相互独立的前缀亲和路由与精确缓存索引。
配置抽屉只显示当前节点的源码、路由或运行参数，包括原生 CPU 缓存每副本容量，选定的变体也可修改。
技术详情中的 **All deployment parameters（全部部署参数）**提供完整渲染参数列表及
**Final YAML（最终 YAML）** 编辑。

自动添加优化时保留每个候选已确定参数的服务拓扑；其他拓扑作为独立候选比较，
不会替换拓扑却继续使用旧角色参数。Inventory 控制器安装需要明确选择。
不支持的传输与缓存组合会被排除，但不阻止其他兼容候选；用户指定的必选项不会被悄悄取消。
Router 的受限认证 RBAC 随部署命名空间管理，清理时也会等待这些资源被垃圾回收；
所有权冲突会明确报错，不会覆盖已有授权。

Manual 不以负载收益为兼容性门槛，选择兼容的源码优化，同时保留明确排除项和用户编辑。
外部前置条件、未确定的选项及资源检查仍会限制生成。Agentic 按负载推荐，使用相同编辑器。
两种模式都考虑负载预设之外的兼容源码优化，但不自动安装外部前置依赖。
**Apply changes and check resources（应用修改并检查资源）**生成新的已审阅源码快照；
未应用修改会阻止部署。改变优化选择时，不相关的最终参数编辑会合并到新渲染资源中；
冲突编辑会明确报错并阻止应用，不会静默丢弃。请撤销冲突选择，或在技术详情中使用
**Discard final parameter edits（丢弃最终参数编辑）**。
旧快照没有编辑基线时，基础配置变化需要明确处理。禁用原生 CPU 缓存会保留容量，供再次启用。
源码版本变化后，
必须明确选择丢弃源码编辑并采用当前版本，才能继续。

流程图上方的横向摘要集中显示拓扑、资源、优化数量与校验状态。
**Review & deploy**在同一个窗口打开 YAML 和 **Deployment summary（部署摘要）**，
集中显示容量、缓存、警告和 **Confirm deployment** 确认操作。请选择模型服务的 **Inference Service（推理服务）**，不要选择 EPP 或
指标服务。审批绑定所选端点和准确配置校验和，并重新检查容量；编辑器没有独立部署通道。
旧计划提供 **Load Guides and build source configuration（加载指南并构建源码配置）**，
原预览保留在折叠区域。源码目录不可用时显示真实错误，不会用旧模板冒充完整源码组合。
折叠的 **More planning tools / optional（更多规划工具，可选）**保留 Agentic 的
**Alternatives（候选方案）**和 **Benchmark tests（基准测试）**。候选方案比较已审阅的源码配置及证据。

Agentic 提供独立可选的 **Benchmark tests（基准测试）** 视图，在此准备允许测试的计划，
再选择负载并单独确认执行。加速器上限默认
来自规划约束或发现的容量；容量未知时需要明确填写。已有测试恢复其记录的负载和预算。
提交前检查重复次数所需预算、资源上限和数值范围。测试中断或清理失败时，必须先完成清理
再开始新的测试；已提交正式部署的方案不能再次开始试验。测试证据展示实测 TTFT、TPOT、
端到端延迟、吞吐和错误比例，缺失值保留未知。
源码方案必须先使用 **Check all source candidates（检查全部源码候选）**渲染候选，
并为每个已选候选选择其审阅过的推理 Service。缓存变体必须在指南配置中编辑并渲染，
测试不会悄悄添加未经审阅的 native 缓存变体。选择实测优胜方案会恢复其准确源码配置。

**Workload and limits（负载与限制）** 显示发现的容量与当前上下文设置，不虚构流量值。
加速器限制会影响哪些组合能够容纳；请求长度与并发用于细化容量估计；
QPS 和延迟设置性能目标。留空不增加约束，点击 **Rebuild plan（重建方案）** 应用覆盖值。
折叠的 **Planning log（规划日志）** 保留诊断事件；Manual 不再显示单独无意义的 **Plan** 导航按钮。
在成功生成替代方案前保留当前方案；
**Keep existing plan（保留现有方案）** 返回原方案。新配置修订需要重新审阅。
**Review & deploy**打开当前准确配置的审阅窗口，点击 **Confirm deployment**提交。
校验和变化后必须重新审阅。确认后，
**Deployment execution（部署执行）** 展示 Deploy 实际运行和组件状态、
尝试次数及失败原因。有执行记录后可以打开 **View Pods & Logs**，也可通过
**Open deployment** 跳转到已筛选的部署列表，继续监控和评测。
只有 Deploy 执行成功且所有组件报告就绪，摘要才显示 **Deployment ready（部署就绪）**；
规划状态不代表就绪，负载性能仍需测量。


## 打开部署创建流程

1. 在左侧导航中，打开**部署**。
2. 在页面标题栏，点击**创建**。
3. 按[创建部署](/user-guide/model-market)完成操作。提交后，新部署会出现在列表中。

Manual 直接进入部署方案；Agentic 先提供目标选项，所有数值参数都可选。不预设请求长度、前缀复用或负载形态，
这些是收益参考而非兼容性门槛。Agentic 选择 AI 提供方后，
可从自然语言目标提取明确表达的定性负载特征，提取结果可见、可修改。
未使用 AI 时依赖结构化输入；数值资源上限和性能目标不会由 AI 推测。

Manual 在已支持组合中选择源码校验后优化覆盖最多的方案，而非第一个能渲染的 Guide。
这不等于占满集群，也不代表实测最优。不支持的组合会明确说明。
**Ready for your confirmation（等待确认）**给出简洁结论；检查失败时阻止部署并提供 **Retry checks（重试检查）**。
部署确认会重新检查当前资源。

前缀亲和路由、P/D 分离和 CPU KV 卸载可以独立组合。路由组合保留 P/D 调度配置，
并使用同一固定源码版本中的亲和插件；插件或镜像不兼容会明确报错。
基础注意力 KV 缓存与跨请求前缀缓存、CPU 卸载不是同一功能。
vLLM 源码未显式配置的运行开关可在添加强制启动能力检查后配置；
检查在选定镜像内执行，不代表运行时支持已验证。

共享创建流程使用软性同节点放置偏好。已有部署 API 和独立 Configuration 编辑器
保留放置控制。TP 设备由各模型服务 Pod 请求；部署前的计划放置不会显示为实际放置。

## Guide 入口选择

自动选择通用入口时，优先使用根目录（`.`），其次使用 `base`。如果两者都不存在，
部署会明确报告 Guide、硬件 profile 和可用变体，而不是自动选择某个平台的专用配置。
此时应选择兼容的 Guide 源码，或在支持显式选择的流程中指定已列出的变体。

Agentic 的分层前缀缓存表达 native CPU 缓存需求，不固定源码目录布局。
Lens 会根据所选源码解析 `native/cpu` 或 `native/cpu/base`，并兼容旧路径。
缺少对应入口时会报错，不会替换为其他缓存实现、存储层或平台专用配置。

## RuntimeClass 策略

RuntimeClass 发现与策略覆盖仅通过后端 API 提供，Manual 和 Agentic 表单不提供
RuntimeClass 输入项。发现接口、策略模式和请求示例请参阅
[部署 API 参考](../api-reference/modules/deployments.mdx)。

## 在列表中查找部署

1. 查看页面顶部的汇总卡片：**总计**、**就绪**、**进行中**、**失败**和**已清理**。
2. 在列表工具栏中，在**搜索部署**中输入内容，可按名称、描述、模型、命名空间、指南或 ID 匹配部署。
3. 打开**状态**以按部署状态进行筛选。
4. 打开集群选择器，选择**所有集群**或某一个集群。
5. 如有需要，更改**每页行数**，并使用分页器在列表中翻页。
6. 如果没有匹配的行，点击**清除筛选**。

**集群**和**命名空间**列各带一个复制按钮。

## 查看部署详情

1. 在部署行中，打开操作菜单并选择**查看详情**。
2. 在抽屉中，查看**基本信息**、**模型与服务引擎**、**集群与环境**、**网络与端点**以及**审计与时间线**各个部分。
3. 当你需要在别处复用诸如**命名空间**、**集群会话 ID**、**容器镜像**、**内部端点**、**转发端点**或**执行 ID**等值时，使用这些值旁边的复制按钮。
4. 如果部署失败，请先阅读失败提示横幅，再做任何改动。

等待状态变为 **Ready（就绪）**后再调用。处于 **In progress（进行中）**时，
打开 Pod 日志查看启动进度；处于 **Failed（失败）**时，结合失败提示和对应 Pod 的日志排查。

状态灯同时反映模型服务器 Pod 的实时状态：黄色表示就绪的模型服务器 Pod 少于请求数量，
服务能力下降；红色表示已没有就绪的模型服务器 Pod，服务不可用。这两种情况也会出现在 **Needs attention（需要关注）**中。

**Failed（失败）**并非终态。发布超过进度期限会被记为失败，但工作负载往往会自行恢复——
例如某个 Pod 一直崩溃，直到其模型缓存补齐后才正常启动。Lens 会持续拿失败的部署与集群实况
比对，一旦其 Pod 重新提供服务就把状态改回 **Ready（就绪）**，因此不必急于重建部署。
如果命名空间已不存在，则该部署会被更正为 **Cleaned（已清理）**。

当 Pending Pod 正在等待加速器资源时，包括 DRA 调度器报告的
`cannot allocate all claims`，即使超过发布进度期限，部署也会保持**进行中**。
刷新先前被标为**失败**的部署时，如果当前诊断确认仍在等待资源，状态会恢复为**进行中**，
调度原因仍可在诊断中查看。这不会释放其他部署占用的设备；需要停止或删除不再使用的部署来
释放资源。容器崩溃和镜像拉取失败仍被视为失败；仅有 Pending 状态不足以判定为资源等待。

调度成功后，Running Pod 可能仍在加载模型，尚未 Ready。如果发布报告超出进度期限，
只要当前容器仍在 `startupProbe` 的启动预算内（没有启动探针时使用 `readinessProbe` 的预算），
Lens 就会保持**进行中**，不会自动清理。预算从各容器实际启动时刻计算，Pending 等待时间
不会占用该预算。当前崩溃、镜像拉取失败、容器重启或探针预算耗尽不适用此宽限。
仅有 Running 状态不代表就绪，仍需通过 provider 的就绪检查。

## 查看 Pod 并查看实时日志

对于新渲染的部署，所有 provider 都会将显式设置的最大模型长度、最大序列数、显存利用率、
块大小和最大批处理 token 数传给 vLLM。P/D 分别应用 Prefill 和 Decode 的配置。
角色配置覆盖 Guide 默认值；角色未指定最大长度时使用模型级最大长度。
定向自定义参数优先，未设置的字段保留上游默认值。这不会重写现有 Pod 或精确发布的清单；
需要创建新部署才能应用变更。排查 KV cache 容量错误时，应核对模型容器启动命令及日志。

Lens 会检查所有部署 provider 渲染的模型服务 Pod 的 `/dev/shm`。普通渲染中，
如果缺少挂载且未启用主机 IPC，会补充每个 Pod 独立的内存型 `emptyDir`，上限为
**4 GiB**；`baseline-vllm` 的默认值也为 4 GiB。这避免了容器运行时默认的
64 MiB 共享内存限制，不会启用主机 IPC，也不会修改上游 Guide 仓库。

已有挂载及其容量设置保持不变，包括未显式设置上限的内存卷和其他卷来源。
未设置上限、其他卷来源、只读或子路径挂载，以及已启用主机 IPC 的情况，会在服务日志和
部署诊断（`snapshot.shared_memory`）中记录警告。内存卷省略 `sizeLimit` 并不表示
上限为 64 MiB，也不表示内存无限可用。重复的 `/dev/shm` 挂载和无效卷绑定会被拒绝。

原样发布清单（`officialGuide`）只检查，不自动补充共享内存挂载；缺少挂载时记录警告。
检查报告也保存在部署产物的
`rendered_payload.value.deployment_contract.sharedMemory` 中。
卷按实际使用量消耗内存，而非提前占用整个上限；规划 Pod 内存时应将共享内存计入。
已有部署仍保留原始清单，需重新创建才能获得新默认值或缺失挂载的补充。

1. 要在行内查看 Pod 状态，点击提示为**显示 Pod** 的行展开开关。
2. 在展开的行中，查看 Pod 表格的列：**Pod**、**状态**、**重启次数**、**节点**和 **Pod IP**。
3. 要使用完整的日志查看器，打开操作菜单并选择**查看 Pod 与日志**。
4. 使用节点筛选或搜索框找到需要查看的 Pod。
5. 点击某个 Pod 卡片，打开该 Pod 的**Pod 日志：**。
6. 如果某个 Pod 包含多个容器，请选择所需的**容器：...**条目。
7. 选择**100 行**、**200 行**、**500 行**或**1000 行**以更改日志尾部的长度。
8. 如果需要查看上一个容器的日志，请打开**上一个**开关。
9. 保持**自动刷新 (5 秒)**开启，以让 Pod 列表和日志保持实时更新。
10. 使用**筛选日志行...**来缩小日志输出范围，或点击**复制**来复制当前的日志文本。

## 优雅停止默认配置

Lens 为模型服务器 Pod 设置 **120 秒**终止宽限期和 **5 秒** preStop 延迟；vLLM 容器的启动命令如果是单条可识别的 `vllm serve` 或 `python -m vllm.entrypoints...`（包括 `sh -c` 脚本），还会设置 `--shutdown-timeout=90`；复合 shell 脚本、无法识别的入口以及已有的非字面量取值保持不变，并在部署时给出警告。缩容、滚动更新或节点驱逐时，Kubernetes 会先把 Pod 从路由中移除，vLLM 随后最多用 90 秒完成进行中的请求。在此默认配置引入前创建的部署需要重启或重新创建才能获得这些设置。SGLang 不支持该 vLLM 参数，因此仅适用端点移除和终止宽限期。对于 P/D 部署，请先缩容 Decode 再缩容 Prefill。当模型容器包含 `--kv-transfer-config` 时，Lens 会在该 JSON 中设置 `kv_load_failure_policy=recompute`，使 Decode 在 Prefill 的 KV 传输失败时本地重算。

3. 等待成功提示**本地端点已连接**出现。

## 扩缩容部署

1. 在部署行中，打开操作菜单并选择**扩缩容**。
2. 对于 P/D 部署，设置 **Prefill replicas** 和 **Decode replicas**；对于聚合部署，设置 **Replicas**。
3. 点击**扩缩容**。

手动扩缩容只修改运行中的 Kubernetes 模型服务器副本。重启部署后会恢复配置中的副本数。DisaggregatedSet 部署创建时固定 `slices: 1`；手动扩缩容只修改角色副本数，永远不修改 `spec.slices`。对于 P/D 部署，请先缩容 Decode 再缩容 Prefill；Prefill 缩容可能中断进行中的 KV 传输，但只要存在 `--kv-transfer-config`，Lens 就会配置 `kv_load_failure_policy=recompute`。

## 打开部署监控与性能分析

1. 在部署行中，打开操作菜单并选择**监控**。
2. 如果监控尚未安装，点击**安装**。
3. 如果监控已存在但处于暂停状态，点击**启用**。

   在部署本身就绪之前，**安装**和**启用**均不可用——监控采集的是该部署的 Pod，
   在此之前没有任何数据可采集。等待期间菜单中会给出相应提示。
4. 当监控已启用时，使用**打开 Grafana** 或**打开 Prometheus** 在新标签页中打开相应的仪表盘。
5. 点击**性能分析**，跳转到该部署的性能分析视图。
6. 使用**禁用**可以在不卸载的情况下停止监控。
7. 使用**卸载**可以从该服务中移除部署监控。

## 审阅生成的部署配置

Manual 使用上文所述源码编辑器，可明确排除前缀缓存或分块预填充，不虚构负载特征。
补全只修改源码支持的设置，不可用选项在指南和优化列表中保留原因。
显式运行参数优先。跨 Guide 组合支持同一固定官方版本中的“优化基线、精确路由或 NIXL P/D + 原生 CPU KV 缓存”，要求运行镜像相同。P/D 的 Prefill 和 Decode 均使用 MultiConnector，按顺序保留原 NixlConnector 并添加 OffloadingConnector，保留传输设置并为每个模型 Pod 预留本地缓存内存。同镜像初始化容器在启动前检查连接器导入及配置结构，并拒绝已知存在卸载缺陷的 vLLM 0.19.0（上游 #39500/#39617）。该检查不代表 GPU 正确性或性能验证。不支持的传输返回具体适配器错误，不支持任意连接器叠加。生成组合配置不代表性能最优。

P/D 的 CPU 缓存适配器目前要求两个角色均使用 `NixlConnector` 和 `kv_both`。
使用 `kv_producer`、`kv_consumer` 的源码仍可用于不叠加 CPU KV 卸载的 P/D 候选；
被拒绝的仅是额外缓存组合。Lens 不会改写这些传输角色，也不会静默删除用户明确要求的缓存功能。

通过节点参数按钮或 **All deployment parameters（全部部署参数）**编辑，再点击
**Apply changes and check resources（应用修改并检查资源）**。Manual 和 Agentic 均保留
已审阅源码包；编辑器不会悄悄把参数修改交给 LLM 或替换为其他候选。
只有明确重建负载需求时才请求新推荐。选择候选不是部署，**Review & deploy**仍需确认。

## 实测比较 Agentic 候选

打开 **Verify with real benchmarks**，选择候选，填写 GPU 上限、最长分钟数、
压测运行次数和重复次数，再选择吞吐、P95 端到端延迟或每加速器吞吐作为目标。
源码候选需要已审阅的推理 Service 和已渲染缓存变体。只有旧计划仍提供可选 CPU
缓存预算来增加测试变体，其运行次数预算应包含额外测试。
合成负载优先使用方案的平均输入 / 输出长度和并发；缺失时分别采用输入 512 token、
输出 128 token、并发 4，请求数为 100。恢复的测试使用已记录的负载。展开
**Test workload** 可修改，或填写代表真实业务的 inference-perf YAML；
缓存实验建议使用能体现前缀复用的实际负载。

**Start deployment and benchmark tests** 会创建真实集群资源。每个候选按相同
负载重复压测，清理后再测试下一个。只有完成全部重复且满足延迟 SLO 和错误率
约束的候选才进入排名；缺少指标和失败测试不会被当作优势证据。结果保留压测 ID，
选择最佳已测候选后，仍需要审阅并确认最终部署。

**Stop and clean up** 停止任务。清理可能超过测量预算；清理失败会阻止继续部署。
任务审计保留配置、负载和进度。服务中断后，任务标为中断并提供显式清理入口，
不会自动恢复部署。同一浏览器会话刷新页面可恢复当前方案。这是有预算的候选
搜索，不是无限自主调整或全局最优证明。

Overview 和 3D 分别展示每个角色的传输及本地 CPU 缓存。Agentic 的 CPU 缓存试验包含符合条件的 P/D 候选，使用相同负载比较原配置与组合配置。默认 NIXL 优先的顺序在多个连接器均命中时优先传输，不保证减少网络传输；正确性及性能仍需实际测量。
